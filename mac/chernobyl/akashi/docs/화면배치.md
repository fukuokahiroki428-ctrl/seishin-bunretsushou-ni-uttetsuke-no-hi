# 화면 배치 — 액자 · 벽돌 · 자동 배치

한이시키의 화면은 `resources/html/index.html` 한 파일이다. 설정 화면과 기능 화면 열넷이 모두 **액자**로 되어 있고,
창 폭에 따라 스스로 모양을 바꾼다. 이 문서는 그 짜임과 까닭, 그리고 점검하는 법을 적는다.

## 1. 액자 틀

| 화면 | 짜임 | 커밋 |
|---|---|---|
| 설정 | `.settings-board` > `.sg[data-group]`(묶음 여섯: 저장·백업 / 원격·NAS / AI / 계정 / 유지보수 / 화면) · 위의 `.settings-filter` 칩으로 한 묶음만 보기 · 기록은 좁으면 한 줄 서랍, 1600px 이상이면 오른쪽 기둥 | `757d52d` |
| 기능 열넷 | `.tab-content.fx` > `.fx-board`(내용 액자 `.fx-frame`) + `.fx-run`(단추 줄 · 진행 · 결과 · 로그) | `fc6bd9d` |

칸 하나짜리 액자(`.fx-frame[data-single]`)는 제목이 곧 칸 이름이라 안의 이름표를 숨긴다. 이식(graft) 층이
`.section-label` 에 `display:flex !important` 를 걸어 두어 `!important` 로만 이긴다.

## 2. 한 쪽 스크롤 · 벽돌 쌓기 (`6f0f90b`)

사용자: "스크롤 안에 스크롤이 있으니 불편하도다 — 스크롤 안에 액자가 있도록". 그래서 **액자 안에서는 스크롤하지
않는다**(`.fx-body { overflow: visible }`). 페이지 하나만 스크롤한다. 예외는 로그 상자뿐이다(로그는 본래 흐르는 것).

키가 다른 액자를 격자에 그냥 두면 짧은 액자 밑이 빈다. 그래서 **벽돌**로 쌓는다.
- 격자를 4px 줄로 잘게 나눈다(`grid-auto-rows: 4px; grid-auto-flow: row dense`).
- 화면 JS `layoutFrames()` 가 액자마다 제 키만큼 줄을 차지하게 한다(`grid-row-end: span ceil((키+14)/4)`).
- 액자는 `align-self: start` 라 줄 수를 바꿔도 **제 키가 변하지 않는다 — 되먹임이 없다.** 이게 없으면 줄 수가
  키를 바꾸고 키가 줄 수를 바꾸는 고리가 생긴다.
- 한 열일 때(`data-cols="1"`)는 벽돌을 끄고 제 키대로 둔다.

설정 화면이 3276px 에서 2265px 로 줄었다.

## 3. 자동 배치 — 폭에 따라 세 단계 (`20dd34e`)

사용자: "다른 앱들 하는것좀 보고 와라 자동으로 창 바꿔주고 하는것들 많은데". 예전엔 `@media (min-width:1100px)`
하나로 갈라, 좁히면 세 열이 억지로 끼고 「시작」 이 한참 아래로 밀렸다. 메신저 · 코드 편집기 · 다운로드 관리자가
하는 방식을 옮겼다.

| 모드 | 조건(남은 폭) | 모양 |
|---|---|---|
| 넓음 `wide` | 860 이상 | [내용 1~3열 \| 실행 기둥(붙박이 sticky)] — 기둥 폭 300~400 |
| 보통 `mid` | 560~859 | 위 띠 `.fx-bar` 에 단추 · 실행·로그는 **아래 패널**(sticky bottom) |
| 좁음 `narrow` | 560 미만 | 위 띠의 **[설정][실행]**(`.fx-seg`)으로 하나씩 |

- **폭은 창이 아니라 스크롤 영역의 실제 폭**으로 잰다(`fxAdapt()`). 창 폭 944~1888pt 에서는 앱이 배율을 맞춰
  (`MainWindow::zoomForWidth` = clamp(창폭/1180, 0.80, 1.60)) 화면 안쪽 폭이 늘 1180px 쯤이다. 사이드바가 접히거나
  기능 창이면 또 다르다. 그래서 `@media` 가 아니라 JS 가 잰다.
- 스크롤 막대가 생겼다 없어지며 폭이 6px 흔들려 모드가 오락가락하지 않도록 **막대를 뺀 폭은 쓰지 않는다**(`getBoundingClientRect`).
- 열 수는 `floor((판 폭+14)/(300+14))`, 1~3. `data-cols` 와 `--fx-cols` 로 알린다.
- 보통·좁음에서 탭의 `.btn-row` 는 위 띠(`.fx-bar-btns`)로 **옮겨진다**(단추의 id·onclick 은 그대로). 어디까지 스크롤했든
  시작·중지가 보인다. 띠에는 로그 마지막 한 줄(`.fx-status`)이 늘 있다.
- 아래 패널: 위쪽 손잡이 `.fx-grip` 을 끌어 높이를 바꾼다. 높이는 **화면 높이에 대한 비율**로 기억한다
  (`localStorage` 의 `hanishiki.fxDockRatio`) — 창 높이를 바꿔도 같은 몫. 「로그」 이름표나 손잡이 두 번 누르기로 접는다
  (`hanishiki.fxDockMin`). 창이 낮아져 최소 높이(140px)에 걸려도 기억한 비율은 바뀌지 않는다 — 사용자가 끌 때만 바꾼다.

### 저절로 넘어가기

`setRunning(platform, running)` 이 끝에서 `fxRunState()` 를 부른다.
- 좁음: 시작하면 **실행 화면으로 넘어간다.** 보통: 접힌 패널이 **펴진다.**
- 설정을 보는 사이에 끝나면 [실행] 위에 초록 점(`fx-done`). [실행] 을 누르면 지워진다. 도는 동안은 파란 점이 깜박인다(`fx-running`).
- 시작이 검사에서 막히면(대상 없음 등) `setRunning(true)` 이 불리지 않으니 넘어가지 않는다 — 고칠 곳(설정)에 머문다.

## 4. 대상 목록 한 줄 (`@container`)

체크 · 번호 · 아이디 · 별명 · 계정 · ▸ · × 일곱 칸이 290px 에 안 들어가 두 줄(67px)로 접혔다. 17명이면 대상 액자만 1380px.
목록(`.account-list`)을 **컨테이너**로 삼아 목록 폭으로 잰다. 240px 이상이면 한 줄(33px), 400px 미만이면 번호를 숨긴다.
남는 폭은 아이디가 먼저 가져간다. 17명 → 786px.

## 5. 알려진 함정

- 진행 막대의 기본 폭은 100% 다. 실행 액자 안에서 옆 여백 14px 가 더해져 **오른쪽 끝이 14px 잘렸다**(다 차도 끝이 안 보임).
  `.fx-run > .progress-bar { width: auto }` 로 고쳤다(`b1cec3a` — 공작함 `check_layout.py` 가 잡음).
- 꺼진 단추(`.btn:disabled`)는 `pointer-events: none` 이다. '가려졌는지' 를 `elementFromPoint` 로 재면 단추를 지나쳐 부모가
  나온다. 점검 공구는 재는 동안만 받게 한다.
- 새 격리 사본은 임시 디스크가 정해지지 않아 첫 실행 안내창(`#disk-modal`)이 화면을 덮는다. `iso.py` 가 `tempDir` 을 넣어
  띄우는 까닭이다(`--first-run` 이면 그대로).

```bash
python3 akashi/check_layout.py --seed-targets 17   # 5폭 × 15화면: 모드·열·시작 단추·옆넘침·잘림·대상 줄 높이
python3 akashi/check_adapt.py                      # 좁음·보통·넓음 움직임 아홉 가지
python3 akashi/shots.py --tabs twitter,settings --widths 1180,800,420 --themes light,dark
```
