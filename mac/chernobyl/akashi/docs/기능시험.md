# 기능 시험 — 기능을 실제로 돌려 보는 시험 (`akashi/tests/`)

`inspect_all.py` 는 화면을 대 보는 정기 점검이다. 이쪽은 기능을 **실제로 돌린다** — 이 맥 안의 시험 사이트를 크롤하고,
실제 Chrome 으로 캡처하고, 받는 도중 앱을 죽이고, 가짜 프로세스를 세워 정리 규칙을 잰다. 모두 격리 사본에서 한다.

```bash
cd mac/chernobyl
python3 akashi/tests/run_all.py                       # 다섯 가지(약 8분)
python3 akashi/tests/run_all.py --only crawl,viewer   # 고른 것만
python3 akashi/tests/crawl.py                         # 하나만 — 출력이 그대로 보인다
```

## 언제 돌리나

- 그 기능을 고쳤을 때 — 크롤러 · 이어받기 · SingleFile · 옛 트위터 보기 · 캡처 Chrome 정리.
- 설치 · 판 내기 전에, `inspect_all.py` 와 함께(그것보다 오래 걸리니 매 빌드마다는 아니어도 된다).
- 옛 판과 견줄 때 — `--app <옛 판.app>`. DMG 를 읽기 전용으로 붙여 그 안의 앱을 주면 된다.
  고친 것이 정말 그 문제를 잡는지(옛 판은 실패하고 새 판은 통과하는지)를 이걸로 확인한다.

## 시험

| 시험 | 살피는 것 | 생긴 까닭 |
|---|---|---|
| `capture_cleanup.py` | 앱 시작 · '좀비 Chrome 정리' 단추 · 진단 수가 **이 앱 데이터 폴더의** 캡처 Chrome 만 고르는가. 다른 홈 · 비슷한 이름 · 살아 있는 다른 폴더는 남고, 이 사본의 캡처 · `_pen` · 트랙 · 사라진 옛 폴더의 고아는 꺼진다 | r37 까지 `pkill -f chrome_capture_profile` 이라 시험 사본이 켜지면 사용자 앱의 수집 Chrome 이 꺼졌다(`0aa09aa`). r37 로 돌리면 '남아야 할 것' 다섯이 모두 꺼져 실패한다 |
| `viewer.py` | '옛 트위터로 보기' — 계정 목록 · 계정별 화면 둘 · 로그 완료 줄 · 다시 누르면 바뀐 계정만 · 번들에 `.pyc` 없음 | r37 의 새 기능. `.pyc` 가 번들에 남으면 봉인이 깨진다 |
| `resume.py` | 유튜브 오디오 장부가 따로(`.yt_archive_audio.txt`) — 오디오로 받은 뒤에도 동영상을 받는다. 받는 도중 SIGKILL 해도 진짜 이름으로 잘린 파일이 없다(숨은 `.part`) | 잘린 파일이 '받은 것' 으로 남아 다시 받지 않던 것 |
| `crawl.py` | 끝까지 · 중간에 멈춤(40초 안에 끝 줄) · 늦은 끝 신호가 '중단됨' 을 덮지 않음 · **그림 받는 도중 멈추기 세 번** · 앱이 살아 있음 | 받는 중 멈추면 중첩 이벤트 루프 안에서 크롤러가 지워져 앱이 죽던 것(use-after-free) |
| `singlefile.py` | 실제 Chrome 크롤로 다섯 쪽 + 열 수 없는 주소 — 오류 화면은 저장 안 함, 그림이 모두 `data:` 로, 지연 그림(IntersectionObserver) · 다른 출처 그림 · 엄격한 CSP 쪽도 | 크롬 오류 화면이 '캡처 완료' 로 저장되던 것, 최소화된 창에서 그림이 반만 들어가던 것 |

모든 시험은 끝에 **사용자 앱의 Chrome(9223)은 그대로** 를 판정한다(viewer · resume 은 Chrome 을 띄우지 않아 뺀다).

★ **화면이 잠들어 있으면 `singlefile` 의 지연 그림 쪽(io.html)은 0/6 로 실패한다.** macOS 가 화면을 끄면 그리기를 멈추고,
최소화된 캡처 Chrome 의 IntersectionObserver 는 그릴 때만 판정하기 때문이다. 옛 판(1.22.98)도 새 판(1.28.1)도 같다
(2026-10-06 실측 — 같은 밤에 둘 다 0/6, 나머지 네 쪽은 같음. 헤드리스로는 여섯 조합 모두 6/6). 시험은 사람 입력이 5분 넘게
없으면 미리 알린다. **실제 수집도 같다** — 밤새 화면이 꺼진 채 캡처하면 스크롤해야 뜨는 그림이 빠질 수 있다.

## 지키는 것

- **사용자의 앱 · 자료 · Chrome 을 건드리지 않는다.** 시험마다 사본을 새로 띄우고(`iso.py start` — 다른 홈) 끝나면 지운다.
  끄는 것은 사본의 PID(기록 대조)와 시험이 `Popen` 으로 띄운 가짜뿐이다. 이름으로 찾아 끄지 않는다.
- **옛 판 + 사용자 앱이 수집 중이면 시작하지 않는다**('못 돎'). 시험할 앱이 캡처 정리 고침(`0aa09aa`) 전의 판(실행 파일에
  `chrome_capture_profile_pen` 이 없음 — `--app` 의 옛 판이든 묵은 `build/` 든)인데 사용자 앱의 캡처 Chrome(9223 · 트랙 · 출구 ·
  PEN 어느 것이든)이 떠 있으면 그렇다. 그 판의 사본은 켜지는 순간 이름으로 끈다.
- **바깥으로 나가지 않는다.** 시험 서버는 `127.0.0.1` 의 빈 포트, 바깥 주소는 `example.invalid` 뿐. 시험 영상은 번들
  ffmpeg 로 그 자리에서 만든다.
- **진짜 자료를 쓰지 않는다.** 트위터 보관 폴더는 지어낸 두 계정(`fixtures.build_fakearch`)이다.
- 같은 포트(기본 9334)에 떠 있던 사본은 시험이 끈다 — 다른 일에 쓰던 사본이 있으면 `AKASHI_PORT` 로 포트를 달리한다
  (8873~11622 — 그 밖이면 사본의 캡처 Chrome 포트가 사용자 앱 쪽 9223 과 겹칠 수 있어 `iso.py` 가 띄우지 않는다).
- **화면 JS 오류는 켜고 잰다.** CDP 는 `Runtime` · `Log` 를 켜야 예외 · console.error 를 보낸다(`_common.watch_errors`).
  옮기기 전의 시험들은 켜지 않아 '화면 JS 오류 없음' 이 늘 통과했다.

## 재료와 기록

- 시험 사이트 · 가짜 보관 폴더 · 시험 영상은 `$TMPDIR/akashi-tests`(`AKASHI_TEST_DIR`)에 **매번 새로** 만든다. 저장소에는
  시험 코드만 둔다 — 그림 파일을 공개 저장소에 올리지 않으려고, 그리고 임시 폴더는 세션 사이에 비워질 수 있어서다
  (2026-10-05 에 시험 스크립트와 재료가 통째로 사라진 적이 있어 이 폴더로 옮겼다).
- `run_all.py` 는 시험마다 전체 출력을 `<이름>.log`, 사본의 앱 기록을 `<이름>_app.log` 로 그 폴더에 남긴다.

## 시험을 더할 때

- `tests/<이름>.py` 하나 — 머리에 쓰는 법 · 살피는 것 · **★ 왜**. `main()` 이 `0/1/2` 를 돌려준다.
- `_common.Checks()` 로 판정 줄(`✔`/`✘`)을 찍고 `summary()` 로 끝낸다. 사본은 `iso_start()` · `iso_stop()` 으로만.
- 재료는 `fixtures.py` 에 — 매번 만들 수 있게.
- `run_all.py` 의 `TESTS` · `LABEL` 에 이름을 더하고, 이 문서의 표에 한 줄.
- 고친 것을 시험하면 **옛 판으로 한 번 돌려 실패하는 것**까지 본다 — 통과만 보면 시험이 아무것도 안 재고 있을 수 있다.
