# 정비 수칙 — 이 앱을 고치는 사람(사람이든 AI 든)이 지킬 것

사용자의 계정과 자료를 다루는 앱이다. 한 번의 실수가 되돌릴 수 없는 일이 된다. 아래는 실제로 겪은 일에서 나온 규칙이다.

## 계정과 비밀

- **비밀번호 · API 키 · 토큰 · 계정 정보는 정비하는 쪽이 넣지 않는다. 사용자가 직접 넣는다.**
- 쿠키 · 세션 · 토큰 값은 **찍지 않는다** — 일부도 안 된다. 이름 · 길이 · 있음/없음 · 상태 코드만 적는다.
  앱 로그도 그렇게 가린다(`sessionid` 등은 "있음 (N자, 가려짐)").
- 토큰이 든 임시 사본·백업은 쓰고 나면 지운다(`iso.py stop` 은 `--seed-config` 로 복사한 사본을 지운다).
- 고침 꾸러미 서명 열쇠(`~/.config/hanishiki/hotfix_signing_key.pem`, 0600, 저장소 밖)는 찍지도 커밋하지도 않는다.

## 바깥으로 나가는 일

- 푸시 · 태그 · 판 올리기 · 고침 꾸러미 밀기는 **사용자의 허락을 받고** 한다. 한 번의 허락이 다음 일까지 덮지 않는다.
- 공개 저장소다. 올라간 것은 누구나 읽고, 지워도 기록에 남는다. 올리기 전에 `privacy_scan.py`.
  공개되는 스크립트에 사람 이름을 박지 않는다 — 찾을 이름도 실행할 때 뽑는다.

## 사용자의 앱과 자료

- 사용자가 켜 둔 앱을 **묻지 않고 닫지 않는다.** 닫을 땐 osascript 로 곱게(`install.py`). 켠 채로 덮으면 실행 중인 파일이
  바뀌어 SIGBUS 로 죽는다 — 충돌 보고서에 세 번 남아 있다(`crash_report.py`).
- 사용자가 앱을 켜 둔 동안 **같은 자료 폴더를 쓰는 두 번째 앱을 띄우지 않는다.** 설정·색인을 서로 덮어쓴다.
  시험은 격리 사본으로(`iso.py` — 홈·임시 폴더·번들까지 따로).
- 사용자 자료를 **영구히 지우지 않는다.** 치워야 하면 동의를 받고 휴지통으로(Finder).
- 프로세스를 **이름으로 죽이지 않는다.** `pkill -f 앱경로` 는 그 경로를 인자로 받은 codesign 까지 잡아 서명 도중에 죽였고,
  번들이 망가졌다(dylib 16 → 54개). 실행 파일 경로와 PID 로 가린다(`kill_app.sh`, `lib/proc.py`).

## 맥과 윈도우

- 맥 쪽은 `windows/` 트리를 고치지 않는다. 윈도우에 전할 것은 `main` 의 `WINDOWS_HANDOFF.md` 에 적는다.
  윈도우에서 온 것은 `MAC_HANDOFF.md` 에 있다.

## 빌드 · 설치 · 판

| 단계 | 방법 | 알아 둘 것 |
|---|---|---|
| 빌드 | `cd mac/chernobyl && ./build.sh` | 10~15분 · 잠금 `build/.build.lock` · 끝 줄 `=== Done! ===` · rpath·install_name_tool 줄은 해롭지 않은 소음 · 소스를 더하면 `cmake -B build` 부터 |
| 점검 | `python3 akashi/inspect_all.py --doctor --hotfix` | 격리 사본으로 화면 전체 · 배치 · 자동 배치 · 폼 저장 · 서명·도구 · 고침 꾸러미 |
| 기능 시험 | `python3 akashi/tests/run_all.py` | 크롤 · 캡처 · 이어받기 · 옛 트위터 보기 · 캡처 Chrome 정리를 실제로(약 8분) — 그 기능을 고쳤으면 꼭, 고친 것은 옛 판(`--app`)으로 실패도 본다 |
| 설치 | `python3 akashi/install.py` | 켜 둔 앱은 묻고 닫는다 · 대상이 우리 번들일 때만 `rsync --delete` |
| 판 | `python3 akashi/release.py --notes 글.md` | 태그 `mac-<판>-r<번호>`(v 로 시작하지 않음) · `--latest` · 공증 안 됨 |

★ 새 빌드를 **빌드 폴더에서 그대로** 띄우면, 앱의 자가 점검이 번들에 `__pycache__` 를 써 봉인을 깨고 스스로 다시 서명한다.
격리 사본(다른 홈)에서 그러면 키체인이 안 보여 **ad-hoc 으로** 서명된다 — 그 번들로 DMG 를 만들면 macOS 가 '다른 앱' 으로 보고
권한을 초기화한다. `iso.py` 가 빌드본을 복제해서 띄우는 까닭이다. 서명이 ad-hoc 이 됐으면 `bash codesign_app.sh build/<앱>.app`.

### 서명 인증서 — 만료 전에 할 일

- 앱의 신원(designated requirement)은 `identifier "com.hanishiki.app"` + 인증서 이름 `Apple Development: …(748FMV6UG5)` 이다. **같은 이름의 새 인증서**면 권한(TCC)이 그대로 이어진다. Developer ID 를 섞거나 이름이 바뀌면 권한이 한 번 초기화된다.
- 갱신: Xcode › Settings › Accounts › Manage Certificates › `+ Apple Development`(팀 38Y3J47PWT). 확인: `security find-identity -v -p codesigning`.
- 갱신 직후에는 같은 이름의 인증서가 둘 보인다(옛것은 만료까지 유효). codesign 이 '애매하다(ambiguous)' 고 하면 옛것을 키체인에서 내보내 둔 뒤 지우거나 `SIGN_ID=<SHA-1>` 로 고른다. **모든 사본을 새 서명으로 바꾸기 전에는 옛 인증서를 폐기(revoke)하지 않는다.**
- 인증서(.p12, 개인 키 포함)와 고침 꾸러미 열쇠(`~/.config/hanishiki/hotfix_signing_key.pem`)는 **이 맥도 とけてる 도 아닌 곳**(비밀번호 관리자 · 암호화한 USB)에 한 벌씩 둔다. 저장소에는 절대 넣지 않는다. 고침 열쇠를 잃으면 새 판 없이는 고침 꾸러미를 보낼 수 없다.
- 인증서가 없거나 만료되면 `codesign_app.sh` 는 팀으로 서명돼 있던 번들을 ad-hoc 으로 바꾸지 않고 멈춘다(일부러면 `ALLOW_ADHOC=1`). `release.py` · `install.py` 도 ad-hoc 빌드를 받지 않는다.

### 새 맥에서 빌드하기

1. Homebrew: `brew install qt qtwebengine cmake` — 판은 릴리스 알림 끝의 '빌드에 쓴 것' 줄과 맞춘다(Qt 판이 바뀌면 크로미움 · 최소 macOS 도 바뀐다). 맞춘 뒤 `brew pin qtbase qtwebengine cmake`.
2. 서명 인증서(.p12)를 로그인 키체인에 들이고 `security find-identity -v -p codesigning` 로 확인한다. 고침 꾸러미를 낼 맥이면 열쇠를 `~/.config/hanishiki/hotfix_signing_key.pem`(권한 600)에.
3. `gh auth login`(발행 · 태그 푸시).
4. 외부 도구: `bash scripts/download_tools.sh` — 판이 고정돼 있다(ffmpeg · ffprobe · deno · rclone · exiftool). yt-dlp 래퍼는 저장소에 있다.
5. 번들 파이썬: `bash mac/chernobyl/scripts/bundle_python.sh` — 저장소 루트의 `requirements.txt` 판대로 깐다(yt-dlp 와 yt-dlp-ejs 는 짝).
6. 번들 크로미움: README 의 '번들 Chromium 넣기' 절.
7. `cmake -S mac/chernobyl -B mac/chernobyl/build` 뒤 `cd mac/chernobyl && ./build.sh`. 판 번호(CFBundleVersion)는 build.sh 가 git 태그로 정한다 — 태그를 받아 두어야 한다(`git fetch --tags`).
8. `python3 akashi/tests/run_all.py` · `python3 akashi/inspect_all.py --doctor --hotfix` 가 모두 통과해야 낸다.
