# 수리 도우미 — 무엇이 왜 안 되는지 짚는다 (`c17c84c` · `63eae66`)

사용자: "ai가 너무 멍청합니다" — "기능 고쳐" 에 "도움이 필요하면 말씀해 주세요" 로만 답했다.

## 왜 멍청했나

AI 가 받는 앱 상태에 **무엇이 실패했는지가 하나도 없었다.** 고칠 재료 없이 말만 했다.

## 지금의 짜임 (`HanishikiBackend.cpp`)

1. **최근 문제 모으기** — `log()` 가 오류·경고 줄을 `m_recentProblems` 에 쌓는다(최근 120개, `m_recentMutex` 로 잠금).
   어느 기능인지(`inferPlatformKey`)와 시각을 함께 둔다.
2. **판별** — `diagnoseProblems(기간, 기능)` 이 규칙으로 원인을 가린다. 먼저 고침 꾸러미의 규칙(`repair_rules.json`),
   다음 앱에 든 규칙: VPN(프록시)에 닿지 않음 · 저장 디스크가 안 보임 · 서비스가 응답 형식을 바꿈 · 너무 많이 요청함(429) ·
   네트워크 · 파이썬 · yt-dlp · 로그인. 맞는 규칙이 없으면 "알려진 원인에 없는 오류" 와 기록 한 줄.
3. **말 가르기(`llmChat`)**
   - 고장 이야기(`reTrouble`: 안 돼 · 오류 · 멈췄 · 왜 안 …)면 판별을 앞에 붙여, **기록 한 줄과 함께** 무엇이 왜 안 되는지 짚는다.
   - "고쳐"(`reDoIt`: 고쳐 · 수리 · 해 줘 …)면 안전한 수리를 **바로 한다** — 토큰 다시 뽑기(`refreshAllTokens`) ·
     모듈 업데이트(`updateModules`) · 파이썬 복구(`repairPython`).
   - 앞 말에서 기능을 이어받는다("트위터 안 돼" → "고쳐" 는 트위터).
   - "아직 안 돼" · "여전히" · "또 안" 이면 같은 수리를 되풀이하지 않고 **다음 단계**로(`m_repairRanAt` 로 기억):
     토큰 다시 뽑기 → 로그아웃·다시 로그인 안내, 모듈 업데이트 → 파이썬 복구.
4. AI 에 주는 시스템 글에 `[최근 문제]` 요약(`problemsDigest`)이 들어간다 — 판별에 없는 것도 AI 가 기록을 보고 말한다.

## 규칙 더하기 — 새 판 없이

`mac/chernobyl/hotfix/repair_rules.json` 에 넣고 고침 꾸러미로 낸다.

```json
{"pattern": "Just a moment|cf_clearance|Cloudflare",
 "cause": "사이트가 봇 검사(Cloudflare)를 걸었음",
 "advice": "Chrome 으로 그 사이트를 한 번 열어 사람 확인을 통과하십시오.",
 "action": "refreshAllTokens"}
```

- `pattern` 은 **글자 그대로의 대안**(`가|나|다`)만 — 괄호·별표 같은 정규식 기호는 받지 않는다(앱을 멈추는 정규식을 막는다).
- `action` 은 `""` · `refreshAllTokens` · `updateModules` · `repairPython` 만.
- `cause` · `advice` 에 링크(`http`, `www.`, `@`)를 넣지 않는다 — 낚시 글이 될 수 있다.
- 비밀번호·토큰을 '붙여넣으라' 는 안내는 쓰지 않는다. 계정 정보는 사용자가 직접 넣는다.

## 하지 않는 것

비밀번호·토큰을 대신 넣지 않는다. 사용자의 파일을 지우지 않는다. 바깥으로 무엇을 보내지 않는다.
