# 폼 저장 — 바뀐 칸만 보내고, 합치고, 모든 창에 알린다 (`3512b0a`)

사용자: "그게 아니고 계정 정보가 저장 안된다고" — 팬박스 세션을 넣어도 다음에 켜면 비어 있었다.

## 무엇이 문제였나

화면은 입력 칸 전부를 **통째로** 찍어 `backend.saveFormData(json)` 로 보냈고, 앱은 설정의 `formData` 를 그것으로
**갈아 끼웠다.** 창이 하나면 괜찮다. 그런데 기능 창(`#window=fanbox` 등)을 따로 열어 두면 창마다 제 화면을 가진다.

1. 기능 창에서 팬박스 세션을 넣는다 → 그 창이 저장 → 설정에 세션이 들어간다.
2. 본 창은 옛 화면(세션 빈칸)을 들고 있다. 아무 칸이나 건드리거나 포커스를 잃어 저장하면 → **빈 세션으로 통째로 덮는다.**

자격(세션·쿠키) 칸이 가장 자주 지워졌다 — 한 번 넣고 다시 안 보는 칸이라서.

## 지금의 규칙

화면(`index.html`):
- 복원할 때 받은 값을 **기준값**으로 둔다(`_formBase`). 사용자가 건드린 칸은 `_formDirty` 에 표시한다.
- 저장(`_doSaveForm`)은 **기준값과 다른 칸만** 보낸다. 복원을 아직 못 받은 창(`_formRestored` 가 거짓)은 사용자가
  손댄 칸만 보낸다 — 빈 화면을 저장하지 않는다.
- 다른 창의 알림 `applyFormPatch(json)` 은 그 칸들만 바꾸고 기준값도 옮긴다. **지금 치고 있는 칸(포커스)은 덮지 않는다.**
  알림으로 바뀐 값을 되받아 보내지 않는다(메아리 없음).

앱(`HanishikiBackend::saveFormData`):
- 받은 칸을 설정의 `formData` 에 **합친다**(갈아 끼우지 않는다) → 저장 → `runJsAll` 로 **모든 창**에 `applyFormPatch` 를 보낸다.

## 지켜야 할 것(불변식)

- 저장소에서 칸을 지우는 길은 없다. 빈 글도 '값' 이다 — 사용자가 일부러 지운 것만 빈 글로 들어간다.
- 창이 여럿이어도 마지막에 **바꾼** 값이 남는다(마지막에 **저장한 창**이 아니라).
- 자격 칸의 값은 기록·로그에 적지 않는다(이름과 길이만).

## 점검

```bash
python3 akashi/check_forms.py      # 아홉 가지 — 바뀐 칸만 · 합치기 · 알림 · 포커스 · 복원 전 창 …
```
9번(진짜 두 창)은 기능 창이 열려 있어야 한다. 기능 창은 앱 메뉴에서만 열리므로(화면에서 열 길이 없다) 사람이 하나 열어
두면 그것으로도 대 본다. 자격 칸은 값을 찍지도 바꾸지도 않고 길이만 견준다.

## 윈도우에서는

화면을 따로 띄우는 창(기능 창)이 있다면 같은 일이 난다. 같은 화면 규칙과 같은 `saveFormData` 합치기 · 알리기를 넣어야 한다.
