# 응답 모양 — 바깥이 이름을 바꿔도 버틴다 (`de50f1d` · `3916efe`)

## 여덟 달 동안 조용히 비어 있던 팬박스

팬박스가 응답 이름을 바꿨다. 목록은 `items` → `posts`, 쪽 넘기기(`nextUrl`)는 사라지고 `post.paginateCreator` 로,
글 내용엔 껍데기가 한 겹 늘었고, 사진·파일은 글에 따라 목록으로 왔다. 앱은 옛 이름만 보고 0개를 읽고
**「완료: 포스트 0」** 이라고 적었다. 오류도 아니고 빈손도 아니어서 여덟 달 동안 아무도 몰랐다. 세션은 내내 멀쩡했다.

같은 고장이 어디에 더 숨었는지 훑었더니, 응답 이름 하나만 믿고 읽는 자리가 143곳, 그중 바뀌면 조용히 0개가 되는
자리가 76곳이었다.

## 규칙

1. **이름을 여러 개 댄다.** 바뀔 만한 이름까지 미리 적는다 — `pickArray(body, {"posts", "items", "list"})`.
2. **아는 이름이 하나도 없으면 모양을 훑어 찾는다** — `findArrayOfObjects` (객체 배열 중 가장 그럴듯한 것).
3. **찾든 못 찾든 소리를 낸다.** 못 찾으면 실제로 무엇이 왔는지 칸 이름을 나열한다 — `describe`.
4. **HTTP 200 인데 0개면 '완료' 가 아니라 오류다.** 정말 비어 있는 계정과 모양이 바뀐 응답을 가르지 못하면, 차라리 오류로 적는다.

## 도구 — `src/utils/JsonShape.h`

| 함수 | 하는 일 |
|---|---|
| `pick(obj, {이름…})` | 첫 번째로 있는 이름의 값 |
| `pickArray` · `pickObject` · `pickString` | 형까지 맞는 것 |
| `unwrap(obj, {"post","item","data"})` | 껍데기 한 겹 벗기기 — 없으면 그대로 |
| `findArrayOfObjects(obj)` | 이름을 몰라도 목록 찾기 |
| `idsFromMapOrArray(v)` | `{id: {...}}` 맵이든 `[{id}]` 배열이든 아이디 목록 |
| `describe(v)` | "무엇이 왔나" — 칸 이름만(값은 안 찍음) |

모든 `pick` 은 고침 꾸러미의 별명(`Common::shapeAliasesFor`)까지 펼쳐서 찾는다. 별명이 없으면 빠른 길로 간다.
트위터는 알맹이를 꺼내는 이름 셋(instructions · tweet_results · legacy)이 파일 안에 열두 벌 넘게 복사돼 있었다.
이제 `xInstructions` · `xTweetResult` · `xUserResult` · `xLegacy` 한 곳으로 모았다. 파이썬 도우미(`bluesky_daemon.py`)에도
같은 뜻의 `pick()` · `pick_list()` 가 있고, 모양이 바뀌면 `[모양바뀜]` 을 적는다.

## 이름이 또 바뀌면 — 새 판 없이

1. 증상: 「0개」 · 「[모양바뀜]」 · 수리 도우미가 "서비스가 응답 형식을 바꿈" 으로 짚음.
2. 옛 응답과 새 응답을 저장해(개발자 도구 · 로그) 견준다.
   ```bash
   python3 akashi/shape_dump.py old.json --compare new.json   # 사라진 길 · 생긴 길
   python3 akashi/shape_dump.py new.json --arrays             # 목록 후보
   ```
   값은 찍히지 않으니 결과를 기록에 붙여도 된다.
3. 새 이름을 찾았으면 `mac/chernobyl/hotfix/shape_aliases.json` 에 `{"옛이름": ["새이름"]}` 을 넣고, `hotfix.json` 의 판을 올려
   고침 꾸러미로 낸다(`docs/고침꾸러미.md`). 앱은 12시간 안에 받아 그 이름도 찾는다.
4. 구조가 통째로 바뀌었으면(쪽 넘기기 방식 등) 코드를 고쳐 새 판을 낸다.
