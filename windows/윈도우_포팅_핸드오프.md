# 윈도우 포팅 핸드오프 — Mac(fix/signing-crash-injection)에서 가져올 변경

Mac 쪽(`mac/chernobyl`, `mac/pen`, 브랜치 `fix/signing-crash-injection`)에서 적용한 변경 중
**Windows 포트(`windows/`, v3.0 = origin/main)에 아직 없는 것**을 정리한다.
`mac/맥_포팅_핸드오프.md`(Windows→Mac)의 **반대 방향** 문서다.

핵심 로직은 전부 **Qt6 C++/JS 라 플랫폼 무관 → 대부분 그대로 복사**하면 되고,
외부 프로세스 경로(yt-dlp/ffmpeg)·환경변수·중지 플래그 전달만 Windows 방식으로 바꾼다.

> 검증 근거: `origin/main`(Windows v3.0)의 `windows/src` 에는 아래 심볼이 **0건**이다 —
> `downloadSpaceUrl`, `collectSpacesFromTimeline`, `collectThreadsAuto`, `m_spaceCardTweetUrls`,
> `audiospace`, `maxConcurrent`, `PYTHONUTF8`. 즉 1~4번은 Windows에 통째로 없음.

## 0. Windows에 이미 있어 포팅 불필요 (역방향 — `mac/맥_포팅_핸드오프.md` 가 다룸)
- ✅ **YouTube 댓글 수집** (`--write-comments` + `.comments.txt`) — Windows v3.0에 있음, **맥에 없음**(맥이 가져갈 차례).
- ✅ **YouTube 설명 임베드**(`--embed-metadata`) / `@handle`·`UC` URL 리졸버 — 양쪽 다 있음.

- ✅ **정체 워치독 / GNUBoard 미러(crawlSiteMirror) / 통합 미러** — Windows v3.0가 오히려 앞섬 → 그쪽 문서 참조.

## 1. ★★ Twitter 스페이스 다운로드 — 가장 큰 작업 (Windows에 통째로 없음)
유저가 가장 원하는 기능. 음성 라이브(스페이스) **녹화본**을 yt-dlp 로 직접 받는다(twikit 경로 아님).
참조 구현(전부 플랫폼 무관, 거의 그대로 복사):

### 1-A. `MiyoBackend::downloadSpaceUrl()` — 신규 메서드
- 위치: `mac/chernobyl/src/core/MiyoBackend.cpp:6358`, 선언 `MiyoBackend.h:42`
- 시그니처(★ `running` 인자가 병렬 수집 버그픽스의 핵심):
  ```cpp
  bool downloadSpaceUrl(const QString &url, const QString &outDir, const bool *running = nullptr);
  ```
- 핵심 로직:
  | 요소 | 내용 | Windows 적응 |
  |---|---|---|
  | **ffmpeg 필수** | 스페이스는 m3u8(HLS) → ffmpeg 로 mux. **실제 존재하는** ffmpeg만 `--ffmpeg-location` 으로 지정(없으면 PATH). | 맥은 `appDir/ffmpeg`,`/opt/homebrew/bin/...` 후보 탐색. **Windows는 번들 `tools\ffmpeg.exe` 경로**로 교체. (없는 경로를 가리키면 "ffmpeg could not be found" 로 실패하니 `QFile::exists` 체크 유지) |
  | **출력 템플릿** | `-o "<outDir>/%(title).180s [%(id)s].%(ext)s"` `--embed-metadata --no-mtime --no-playlist` | 동일 |
  | **정체 워치독** | 출력이 `STALL_MS=120000`(120초) 없으면 terminate→kill. 전체수집 무한대기 방지. | 동일(`QElapsedTimer`) |
  | **중지 판단** ★ | `if (running ? !(*running) : !platformRunning("twitter"))` 로 종료. | **반드시 `running` 인자 사용** — 아래 1-D 참조 |
  | exe | `Common::ytDlpExecutable()` + `Common::bundledProcessEnv()` | Windows 동일 헬퍼 사용(`yt-dlp.exe`) |

### 1-B. 게시물의 '스페이스 카드' 자동 감지
- 위치: `mac/.../TwitterCollector.cpp:3933` (트윗 카드 파싱부)
  ```cpp
  if (cardName.contains("audiospace", Qt::CaseInsensitive) /* ...broadcast 등 */) {
      if (!tweetUrl.isEmpty()) m_spaceCardTweetUrls.insert(tweetUrl);

  ```
- 헤더 멤버: `QSet<QString> m_spaceCardTweetUrls;` (`TwitterCollector.h:118`)
- 전체수집 시작 시 `m_spaceCardTweetUrls.clear();` (`TwitterCollector.cpp:2409`)
- Windows의 카드 파싱 위치에 `audiospace` 매칭 동일 추가.

### 1-C. `collectSpacesFromTimeline()` — 전체수집 후 스페이스 다운로드
- 위치: `mac/.../TwitterCollector.cpp:2151`, 선언 `.h:60`
- 두 소스에서 스페이스 URL 수집:
  1. (주 신호) `m_spaceCardTweetUrls` 의 status URL — yt-dlp 가 status URL 에서 스페이스 추출(검증됨).
  2. (보강) `<target>_complete.xlsx` 의 text(3)/urls(19)/quoted_tweet_url(25) 에 박힌
     `(?:x\.com|twitter\.com)/i/(?:spaces|broadcasts)/([A-Za-z0-9]+)` 정규식.
  ```cpp
  const QString outDir = userDir + "/spaces";
  for (const QString &u : targets) {
      if (!isRunning) break;
      if (m_backend->downloadSpaceUrl(u, outDir, &isRunning)) ok++;   // ★ &isRunning 전달
  }
  ```
- 'all'(전체) 수집 흐름 마지막에 호출: `TwitterCollector.cpp:2608`.

### 1-D. ★ 병렬 전체수집 중단 버그 — 반드시 같이 포팅
**증상(맥에서 발견):** 여러 대상 병렬 수집(`twitter#0`…) 시, 감지한 스페이스가 시작 즉시 전부 "⏹ 중단"(0/N).
**원인:** `downloadSpaceUrl` 이 중지 여부를 **플랫폼 집계 플래그**(`platformRunning("twitter")`)로 판단 →
병렬에선 트랙이 살아있어도 플랫폼 플래그가 false 라 오판.
**수정:** 다운로드가 **그 트랙의 실행 플래그**로 중지 판단하도록 `const bool *running` 를 받아
`collect()` 에 넘어온 `isRunning`(병렬은 `m_isRunning[parallelKey]`)을 `&isRunning` 으로 전달.
→ Windows에서도 병렬 수집을 한다면 동일하게 트랙 플래그 포인터를 내려야 함. (커밋 `a9ede9a`)

### 1-E. UI — 트위터 입력 유형에 `space`/`thread` 추가
- `mac/chernobyl/resources/html/index.html`: 트위터 type 셀렉트에 `space`,`thread` 추가 + `twitter-url-field`.
- Windows `windows/resources/html/index.html` 에 동일 항목 추가(스페이스 단건 URL, 스레드 URL 입력).

## 3. 설정: 동시 다운로드 개수 옵션 (`maxConcurrent`)
플랫폼별 동시성을 사용자가 직접 조절. Windows에 통째로 없음.
- **Config** (`Config.h:105-106,130` / `Config.cpp:200,232`):
  ```cpp
  int  maxConcurrent() const { return m_maxConcurrent; }
  void setMaxConcurrent(int n) { m_maxConcurrent = n; }
  int  m_maxConcurrent = 0;        // 0 = 플랫폼별 기본값
  // toJson:  root["maxConcurrent"] = m_maxConcurrent;
  // fromJson: if (obj.contains("maxConcurrent")) m_maxConcurrent = obj["maxConcurrent"].toInt(0);
  ```
- **platformSem override** (`MiyoBackend.cpp:85~106`): `maxConcurrent()>0` 이면 모든 플랫폼 세마포어 한도를
  그 값으로 override. `m_platformSemCap` 맵으로 **실행 중 라이브 조정**(release/tryAcquire).
- **UI** (`index.html`): 설정에 `settings-max-concurrent` 셀렉트 + `onMaxConcurrentChange` 추가.
- Windows `Config`/`MiyoBackend`/`index.html` 에 동일 적용.

## 4. 한글 채널/파일명 유니코드 — `PYTHONUTF8`
맥은 YouTube 등 외부 파이썬/yt-dlp 호출 환경에 `PYTHONUTF8=1`,`PYTHONIOENCODING=utf-8`,`LANG/LC_ALL` 주입
(`.command` 스크립트). Windows v3.0엔 `PYTHONUTF8` 0건.
- **Windows 적응:** `.bat` 래퍼에 `set PYTHONUTF8=1` + `chcp 65001` 로 한글 채널명/파일명 깨짐·다운 실패 방지.
- 한글 채널 1편으로 실검증 필요(맥에서 "한글 채널 다운 안 됨" 이 이 문제였음).

## 5. Pen / 미러 — 양방향 검토 (단방향 포팅 아님)

맥의 **Cloudflare 챌린지 대기 루프**와 **브라우저-세션 fetch(자산 41943040B 캡, 최종 패스 링크 재작성)** 만 흡수.
